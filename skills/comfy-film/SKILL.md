# ComfyUI film pipeline

**Paths first.** This text is written against the author's machine (`I:\Video Generation\Tools`,

`paths.json` in the kit root — `tools`, `comfy`, `python`, `ffmpeg`, `ffprobe` — and substitute those
values for the literals below. A path copied straight out of this document fails on a missing file.

Use `scripts/film.py` (or `scripts/film.cmd`), never recreate controllers or poll ComfyUI through model turns. Python and local startup settings are in `assets/machine.json`. Default portrait canvas: H3 FL2VA Turbo 8, 24 fps, 768x1344; dimensions must be divisible by 32.

## Reviews: mandatory gates

Show actual media before asking through the user-input/menu tool: **Принимаем / Нужно изменить / Отклоняем** (or the user's language). Name the exact frame/version or clip. Without a menu tool, use the same numbered choices. Wait for explicit acceptance; silence/preselection never counts. Ask for the correction/reason if missing.

Review newly generated or substantively edited reference frames **one at a time**: show, ask, STOP. Do not create the next frame or run video while approval is pending. Concept/settings approval does not approve an image. Previously approved unchanged references and frames extracted from accepted videos inherit approval, including deterministic Lanczos upscaling, restrained sharpening and canvas fitting; do not ask again. New generative redraws require review. Record frame approvals in `brief.md`.

Every video candidate needs explicit acceptance; technical success is insufficient. Only `accept` after that reply. Never silently replace accepted media. General generation authorization does not waive frame review unless the user explicitly skips it. The CLI does not enforce image approvals.

## Generate and continue

1. New project only: read [setup.md](references/setup.md), collect missing choices in batches of at most three, then `init` once. Before the questions, check the machine (`setup/install-comfy.ps1 -Modes <mode> -Check`, see install.md) and ask the mode first — video / long / refs / lipsync, detailed in modes.md. A missing model set is an install conversation with the user, never a silent download or a render that fails on a missing file. Reuse supplied choices; delegated settings use the recommended profile. Offer 10/15 seconds plus custom 4–15 including fractions. Persist technical settings in film.json; creative intent, target length and loop choice in brief.md. `doctor` is for installation checks, not every run.
2. Prepare and review references under the gates above. Normally first then last; a creature design may come first. For a multi-part film, delegate the substantive draft prompt package per delegation.md, then review and adapt each continuation to actual accepted endpoints before running it. Write an English H3 prompt using the available H3 prompt-writing skill for substantive design: picture alignment, integrated_multimodal_description, overall_soundscape, non_diegetic_music.
3. Read [commands.md](references/commands.md) for needed CLI syntax. `add` approved references and prompt, then `run` once. Keep controller preprocessing: H3 otherwise stretches first-frame but cover-crops last-frame, causing scale drift.
4. `run` starts the progress panel itself and returns its URL in the `progress` field; always post that URL in the same message as the run/wait update, and reuse it instead of starting another panel. Read [progress.md](references/progress.md) on first use or troubleshooting. `wait` once as a persistent process, awaiting the SAME terminal session in bounded waits. Timeout never authorizes resubmission. Keep chat updates brief; percentages describe sampling steps, not total time. The panel is English by default; in a Russian conversation set `$env:COMFY_FILM_LANG='ru'` before `run` (or open the panel URL with `?lang=ru`), so the page matches the language of the chat.
5. Show returned review video in native preview, obtain acceptance, then `accept`. Routine verification is metadata/decode; `inspect` contact sheets only for motion analysis or troubleshooting.
6. For every continuation of the current video action, default to `add --guide prev --guide-frames 22`: this feeds the ending video frames of the preceding accepted clip, including its last frame, to MiniMaxH3AddGuide so motion carries through the join. The controller trims the repeated guide frames from the new clip during assembly. Use 5 or 39 guide frames only when the action calls for a shorter or longer motion cue. `--guide` cannot be combined with `--first` or `--loop`; an approved `--last` may set the desired ending of the new segment. Approval of the accepted source clip is inherited. Use last-frame-only continuation (`extract --which last --scale 2`, or omit `--first`) only when deliberately starting a new action from a still pose; use an explicit `--first` for a new scene. For a loop, follow the separate `--loop` workflow. Adapt the prompt to the actual accepted ending and avoid abrupt motion changes at joins.
7. Rejection: `reject --reason ...`, revise, rerun only that segment with authorization. No automatic generation retries. If submission is uncertain/status submitting, use `recover`, never blindly `run` again.

## Assemble or publish

- Final upscale is optional and runs only when the user requests it. By default, deliver the native-resolution final using `I:/Video Generation/Tools/skills/comfy-film-dsh/scripts/finalize_delivery.py --no-upscale`; the shared wrapper otherwise starts upscaling, so include this flag when upscale was not requested. Do not add a separate approval question just to skip upscale. When requested, use a single 2× SeedVR2 3B FP16 pass after assembly, without a preceding Real-ESRGAN pass: omit `--no-upscale` and use `--scale 2`. Free the idle ComfyUI server's loaded GPU models before standalone upscaling; never interrupt active jobs. Review temporal stability and identity because SeedVR2 can invent details. Deliver the requested 2× version as primary and retain the native file. Keep segment clips at native resolution for `--guide` continuity.
- Name the native export `<video name>-final-<version>.mp4` and the primary 2× export `<video name>-final-<version>-2x.mp4`. No other suffixes such as `compatible`, `lighting`, `review`, or `fixed`. For a revised final, increment the version; preserve existing versions.
- Deliverable MP4s must use H.264 8-bit `yuv420p` and AAC audio (when present), with `+faststart`, for default Windows player compatibility. Preserve this after every finishing/re-encode step, including lighting correction; verify codec and pixel format with ffprobe as well as decoding. Do not deliver High 4:4:4 / `yuv444p` as the playback copy.
- For final processing, use the `finalize_delivery.py` wrapper (syntax in commands.md) rather than ad hoc assembly/encoding/copy commands. It invokes `scripts/finalize.py` for accepted clips or an existing candidate; use `--no-upscale` by default and enable 2× upscale only on user request. It does not approve or publish media.
- Assembly: read [assembly.md](references/assembly.md) when stitching or fixing joins, plus relevant CLI syntax. Accepted clips only; preserve originals. Before first review, perform the automatic continuity finishing in assembly.md: check pauses and boundary motion, locally smooth justified mismatches, and correct unintended lighting/contrast jumps where the scene permits. Show the finished film for review. Fix a bad boundary locally without regenerating accepted clips unless authorized.
- After the user explicitly accepts the finished final film, proactively offer to publish it to YouTube. Make the offer in the acceptance follow-up; do not upload until the user authorizes publication. Final-film approval alone is not publication authorization. If publication is already requested, continue the authorized YouTube workflow instead of asking again.
- YouTube: read [youtube.md](references/youtube.md) only for publication/management. Use `scripts/youtube.py` and saved direct OAuth, not intermediary services or browser upload. Upload the exact accepted export only with publication authorization; film approval alone does not authorize posting. Before uploading new metadata, show the full saved title and description (including links, hashtags and line breaks) for explicit approval as specified in youtube.md; reuse unchanged prior approval or explicit metadata delegation. Preserve project `youtube.json` and `.pipeline/youtube-upload.json` to prevent duplicates. Reuse unchanged authorized metadata. Verify channel, processing, actual visibility and playlist membership. Credentials stay outside outputs and skill packages.
